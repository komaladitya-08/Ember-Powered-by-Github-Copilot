## Architecture and owner decisions

- GitHub token and the Copilot runtime (BE audit #1, partly closed): the token is never on the runtime's command line (only the variable's name) and no other GitHub credential from Ember's environment reaches the runtime. Every stdio MCP server Ember configures (`hardenedSessionConfig`; the launcher every extension uses included) gets each credential variable (`CREDENTIAL_VARS`: `COPILOT_SDK_AUTH_TOKEN`, `GITHUB_TOKEN`, `GH_TOKEN`, `COPILOT_GITHUB_TOKEN`, the enterprise ones, `COPILOT_CONNECTION_TOKEN`, `COPILOT_PROVIDER_*`) set to "" because the runtime merges the configured `env` over its own. Proved on the real pinned runtime, offline (`scripts/runtime-env-live.sh`, dummy tokens): before, a directly started server and the launcher both held the marker; now neither does, nor does the extension's process, and every credential variable there is empty (the launcher's own environment is read through `/proc/<ppid>/environ`). Logs: the finished line of every Ember log has GitHub-token shapes, `Bearer`/`token=` values and URL passwords replaced (logger.ts), covering error name/code/message/stack/cause, keys, scopes, deep and cyclic values; deeper than 8 levels is "[deep]". Tested on what the real logger writes (logger-redaction.test.ts). The runtime's own shell, file and web tools are not offered to the model (`availableTools`, session-config.ts; pinned in extensions-runtime.test.ts). Tokens from `gh auth token` or the environment remain accepted fallbacks.
  - Still open: the runtime process itself holds the token (observed: its environment has `COPILOT_SDK_AUTH_TOKEN`), and a stdio server is the runtime's child, so it can read that file as the same user; blanking stops inheritance, not that. The pinned SDK (1.0.21) has no `gitHubTokenProvider`/short-lived token support to use instead (a session-level one exists, but model listing and sign-in checks are client-level; not tried without credentials). The SDK's own stderr may echo environment text before Ember redacts it. HTTP/SSE MCP servers' headers are not scrubbed. The credential names are those the pinned SDK and runtime read; an alias of another name is not covered (alias completeness). Redaction by shape and by the provider key's exact text: a secret of neither form is not found.
- Durable account-owned memory needs a persistent ownership format and migration/failure policy. Current-run deletion protection is not restart isolation; graph and vector files are still two writes, but memory.json is the authority and the vectors are reconciled against it on load (docs/MEMORY.md), so a crash between them cannot surface a forgotten fact.
- Super agent: recover the missing original D1–D15 design notes and obtain the owner's answers before implementing project sessions. Support non-Git folders explicitly; do not repurpose hardened desktop workers by enabling coding tools.
- Spoken answers and the approval modes: decided by the owner on 12 November (anyone heard can answer a question that is up; Interactive, Assisted and Autopilot in place of Home's three switches). The points those decisions left open were settled by the integrator for the owner to overrule; PLAN.md §10's ninth round lists each with both sides (“Settled by the integrator, for the owner to overrule”), CLAUDE.md carries them in place, and the owner's review of that list is the open item. Still open from before them (PLAN.md §2 “Approvals”, security review of #143): whether, on Windows and macOS, where Ember can't tell the user from its own speakers, a verified spoken request should still grant its task Voice Match's trust.
