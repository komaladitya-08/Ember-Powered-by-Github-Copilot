# Experimental Windows coding files

This is a disabled, file-only foundation for a future Windows coding adapter. The product does not import or register it. It does not provide a command runner, approve a Windows sandbox, export a result, or make the separate LPAC child/PowerShell compatibility proofs pass.

`WindowsCodingCopy.create({ source, privateBase, protectedPaths, signal, current, limits })` captures a host-selected source directory into a fresh private NTFS directory. `WindowsScopedCodingFiles.create({ copy, signal, current, workspace, limits })` exposes structural `/work` list, full-text read, literal search, create/replace, mkdir, and delete operations. Results contain virtual paths and fixed errors. Native handle tokens and host paths stay in the trusted host.

The native module opens one path component relative to a pinned directory with `NtCreateFile`, `OBJ_DONT_REPARSE`, and reparse-point handling. The initial selection accepts fixed local NTFS drive paths; network paths, device paths, mount/junction/symlink traversal, alternate data streams, ambiguous portable names, special files, and multi-link files fail closed. Ancestor handles remain open without delete sharing. Source file handles allow neither shared writes nor deletes for the capture interval, and enumeration IDs, metadata, complete content reads, and final receipts must agree. Source handles receive no write/delete access. Source directories are never modified or granted new ACLs.

The source cannot overlap the private base or protected roots, checked through canonical volume-GUID paths. Fresh private storage may live beneath Ember's protected app-data parent; only new protected child objects are written there, and the parent never becomes a tool source. Fresh destination objects have protected owner/SYSTEM DACLs, fresh file IDs, one link, and bounded sizes. Their exact native identities and DACLs are audited again for each lease. Hidden/system source entries fail capture so a fresh object cannot erase a source privacy marker. Credential paths and complete decoded file contents pass the shared asynchronous privacy guard before capture; read ranges and searches scan complete text before returning any part. Known binary files remain unavailable to text tools. An opaque privacy generation is captured before source awaits and checked again around asynchronous work, so global Forget permanently revokes the old copy, including metadata leases.

Every broker operation holds both the copy's serialized lease and the caller-supplied `workspace.files` lease. A future command backend must supply a lease that proves all its command writers have stopped. The copy alone cannot provide that process proof. Lease contexts expire when their callback settles. Stop revokes admissions synchronously and drains pending file work. Writes use fresh verified temporary files followed by handle-relative atomic rename; there is no awaited work between the final authority check and mutation. Cleanup deletes only audited private objects by their exact held handles. An uncertain native handle close is a typed terminal error, retains failure, and blocks this experimental boundary until process restart.

Unrelated same-user or administrator processes on the host are outside this boundary. This does not claim a transaction against such processes, protection from a compromised trusted host, directory-fsync crash durability, or a production cleanup/export contract. Fresh copies do not grant an LPAC package SID; a future command backend must separately verify fresh-workspace package access and revocation before broker admission. A Windows product adapter still needs verified process isolation, quiescence, immutable owner/project publication authority, explicit partial review, and integration with production resource disposal before this foundation can be enabled.

The dedicated `experimental-windows-files.yml` workflow runs real native tests on Windows Server 2022 and 2025 independently of the LPAC command runtime. Cases cover real hardlinks, junctions, protected canaries, source replacement, writable source handles, atomic overwrite with an open target, expired handles/leases, full-text secrets, Stop, privacy-generation retirement, bounds, and ACL/hidden-attribute tampering. It skips only on non-Windows hosts; configured Windows failures remain failures. These new files have not yet completed native CI. Server evidence will also remain distinct from testing on the user's Windows laptop.

Local Node 22 validation passed seven native ABI/cleanup-ownership unit cases, scoped TypeScript, and ESLint for all six source/test TypeScript files. Linux integration collection registered all 29 native cases and skipped them by platform. This validates collection and portable failure paths, not native NTFS enforcement. The first real Windows run must establish the drive-root bootstrap and actual rename/ACL behavior before any broader readiness claim.
