## Repairs in this checkout

Remote exit status (`app/remote/commands.ts`): removed the obsolete parser that let printed `ESC ]777;ember-exit;0 BEL` replace a nonzero process exit. Only the child process supplies its exit code and signal now. Fake-process regressions cover stdout/stderr, split markers, success, failure and signal termination on pipe/Linux PTY/macOS PTY launches. The launchers and protocol are unchanged. Real Linux loopback SSH showed false statuses before the fix and correct ones after it; the remote suite passed 13 cases with one system-policy case skipped. Native macOS SSH remains open.

Worker state/lifecycle: desired-state reads and toggles share the window lease; queued requests already at the requested state succeed without mutating it. Pending session creation, tool validation and send waits settle within the Stop/deadline grace, release slots, and clean up late sessions. Regressions cover simultaneous requests, changed/disabled controls, denied approvals, cancellation and successful startup.

Conversation: interrupted generated text, buffered chunks and acknowledgements are retired. Spoken ownership follows the request that starts, and renderer playback callbacks carry the hush generation. Background results retain their cards without cutting a foreground answer. Meaningful short negative clarification replies reach the conversation; formal approvals retain their separate gate. These regressions do not prove word-level heard-content accounting or physical playback latency.

Extension metadata and existing PRs: dotted tool names remain admitted, complete descriptions are pinned and checked live, and plugin authentication/hosted-connector copy names the actual supported flow. #106's bounded window walk and #98's slow-voice cache are reapplied to current code. [PR-RECONCILIATION.md](PR-RECONCILIATION.md) records the resolution of #99/#114 and the limits of that reconciliation.

## Architecture blockers and owner decisions

1. **Runtime token environment:** the pinned SDK injects an explicitly supplied credential into its child environment. Filtering inherited variables alone is insufficient. Session credential RPC needs a supported account identity/revocation validation replacement; persistent account login is not an equivalent privacy-preserving workaround.
2. **Durable account-owned memory:** define ownership in the persistent format plus migration, restart and deletion-failure handling. Current-run guards do not establish cross-account restart isolation. Define graph/vector transaction/recovery semantics separately.
3. **Project sessions (“super agent”):** original D1–D15 design notes were not located in current main. Recover them and obtain owner answers about runtime/account, workspace/edit/network authority, staged versus in-place work, non-Git recovery, retention/resume, budgets and external-session attachment. A separate project-session manager should own durable records, workspace writer locks, approvals, interruption/reconnect and verified artifacts. Hardened desktop workers deliberately have empty workspaces and ephemeral sessions; do not enable coding tools there as a shortcut.
4. **Non-Git first:** preserve concurrent edits with before-images or staging and an explicit retention/restore policy. Do not create a repository or upload a folder just to satisfy a runtime. Git publishing/PR/merge authority remains separate from editing/testing.
5. **Spoken trust:** owner decision still needed for Windows/macOS where Ember cannot distinguish the owner from its own speakers, and for the related CLAUDE.md wording.
6. **Release sources:** owner decision on attaching eSpeak NG source archives remains open.

Copilot is the smaller first adapter; Codex app-server can fit a provider-neutral session/turn/approval contract. This is a design recommendation, not a completed integration or authority to control arbitrary existing ChatGPT conversations. See [Copilot SDK](https://github.com/github/copilot-sdk) and [Codex app-server](https://learn.chatgpt.com/docs/app-server).

## Native validation and design recommendations

- Real held-out microphone recordings: laptop/headset/distant mic, accents/names/numbers, noise, quiet speech, thinking pauses, overlap and short approvals. Measure wake false accepts/rejects, endpoint truncation, recognition harm and Voice Match errors. Include Windows recordings and `node scripts/voice/bench.mjs --kokoro` on the owner's PC.
- Physical playback: first audible response, last audible sample after interruption, chunk gaps, recovery correctness, pronunciation/prosody/naturalness. Synthetic wake fixture measured 199–222 ms WASM / 192–195 ms native; it did not reproduce the historical regression and does not close device/load testing. Proposed quiet-after-interruption target p95 ≤150 ms/p99 ≤300 ms is a future gate, not an achieved result.
- VoiceOver, NVDA, Narrator and Orca; keyboard-only approvals including an ordinary focusable “Always in app” route; reduced motion/transparency, increased contrast/forced colours, mixed DPI, enlarged text, small desktops and Linux compositor fallback. Linux desk screenshots are not a remote accessibility tree; nonvisual operation needs design and native validation.
- Pluma, xed, Mousepad and Notepad++ real accessibility trees; message boxes in CJK, Greek, Arabic, Hebrew and Ukrainian. Preserve fail-closed duplicate-control handling while testing ordinary forms.
- Linux login/logind recovery and lock/unlock; Windows suspend/fast-user-switch/input release; macOS permission revoke/regrant/package identity; constrained-volume persistence and failed/offline reinstall on supported platforms. Automated CI does not establish these sequences.
- Dark-only/no backdrop sampling are intentional choices. Broader text enlargement beyond 130% and macOS Home zoom are recommendations requiring layout/native testing, not regressions inferred from a universal mobile 44-point rule. Follow [Apple accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) and [materials guidance](https://developer.apple.com/design/human-interface-guidelines/materials) without trading readability or consent clarity for decoration.
- Compare turn detection, playback interruption and heard-content semantics with [Realtime conversation guidance](https://developers.openai.com/api/docs/guides/realtime-conversations); this does not authorize cloud audio transmission or imply measured voice parity.
