# Disabled native command output owner

This additive foundation starts from lifecycle `1fe1a9683f012192199052a8b9a974e493481992`. It enables no model tool,
backend selector, Windows coding capability, source-folder grant or snapshot import. Existing runtime verifiers and
their pins remain unchanged and must refuse the changed lifecycle files.

The production factory accepts the sealed fresh profile and host output settings. It creates two unique local byte
pipes with overlapped reads, remote clients refused, host/SYSTEM protected DACLs and a Low mandatory label. Only its
own read-only null input and two synchronous write-only pipe clients enter the explicit inheritance list. The canonical null
device's native object name and zero-byte read are checked before use. No caller handle list, host environment or
credential is inherited; the environment contains only an empty PATH, system Windows directory and private TEMP/TMP.
The host still owns toolchain/image attestation and exact command policy; this is not an executable approval.

The factory retains the actual positive returned PI in an opaque reference bound to the exact live launch context
and profile. A non-consuming Stop witness matcher compares that PI with the held process/thread/PID and excludes
every retained root/job alias before Resume. Creator token capture keeps its existing single-consumer rule. The
genuine Stop receipt retires only positively closed PI numbers from the output alias ledger, before another session
can legitimately reuse them. No native handles are model or IPC fields.

At most one 16 KiB read is outstanding per stream. Nonblocking completion checks enforce separate stream counters
and a shared 256 KiB accepted-output budget before delivery. Reads yield between bounded batches. Only broken-pipe
completion establishes EOF; a successful zero-byte operation does not. Overflow, cancellation, timeout or failed
synchronous delivery aborts only the matching active generation. The internal abort request escapes the launch's
async lease context, so it enqueues actual Stop before a later completion call. They can never produce complete output/check facts.

Pending read/OVERLAPPED storage and retained attribute payloads use owned `koffi.alloc` allocations, bounded
`encode`/`decode` copies and positive `free` completion. No external ArrayBuffer/view is used. Unknown pending or
cleanup retains every allocation; native memory is wiped/freed only after its retaining operation is positively settled.
This follows the stable-pointer contract in Koffi's `doc/output.md`; it does not claim a copying bug was reproduced.

Output closure authenticates the genuine same-run Stop/revoke reference, settles cancellation and every outstanding
overlapped operation, requires both EOFs and positively closes every pipe/input/event handle. Its opaque receipt
contains bounded counts, completeness and a finite reason. Cancelled output can have verified native closure with
incomplete content. No callback, similarly named object or serialized record can attest native Stop or closure.
Profile/tree/assets cleanup and canonical-copy import remain separate obligations.

The synchronous creation interval restores only the exact known, still-open inheritance flags, including after a
creation failure. This non-disposing restoration is the sole recovery allowed inside that interval; no process or
output receipt is issued when creation/restoration is uncertain. A positive PI not yet delegated to Stop permits one
non-disposing termination request. All unknown read/create/cancel/close ownership retains the actual handles,
arguments, buffers and native libraries behind a private permanent first-failure barrier. No ambiguous close retries.
