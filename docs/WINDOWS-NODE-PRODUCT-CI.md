# Windows Node product merge gate

The required Windows Node product workflow runs the final checkout on Server 2022 and Server 2025. Each image has three fresh workers: actual native resources/coordinator/canonical execution, the source Electron Home-to-Host journey, and the complete packaged ZIP Home-to-Host journey. The reusable workflow is called by ordinary CI on pull requests, main and release tags; it has no experiment-branch allowlist. Its aggregate requires the complete matrix to succeed. A missing suite, empty report, skipped/todo case, cancellation, failed test or unknown cleanup cannot count as proof.

Native/product test stdout and stderr are captured privately under a fixed byte bound. Raw assertions, paths and acquisition/report parsing errors are not forwarded; only fixed failures and the closed successful-proof summary are printed. Private reports and runtime scratch are not uploaded.

## Required execution paths

The native leaf runs test/integration/windows-node-product-native.test.ts with EMBER_WINDOWS_NODE_PRODUCT_TEST=1. It uses the default native resource factory, authentic Node assets and the genuine coordinator/canonical bridge. Direct host calls establish native execution, adoption and exit-derived observations; the source Home leaf separately verifies guarded approvals and the Host/SDK check ledger. Native coverage includes copied-file operations and held-target POSIX replacement, unchanged protected canaries, literal argv/root cwd, output/error handling, observed Stop and complete resource/profile/artifact cleanup. The separate seven-case asset proof checks access and ownership denials. Root-only execution supplies no child, shell, networking or dependency-install capability.

The source leaf runs test/integration/project-coding-windows-node-electron.test.ts with EMBER_ELECTRON_WINDOWS_NODE_TEST=1. The fixed development staging CLI authenticates the cache and stages or verifies only the actual development Electron resources directory. There is no production resources-path override. The journey must exercise Home, preload/IPC sender checks, Host intake and original words, command cards and denial, a failing check followed by a copied-file repair and the same passing check, review/export/continuation, and Stop/account/source/mode/Forget invalidations. Original source bytes must remain unchanged.

The packaged leaf runs test/integration/windows-node-packaged-product.test.ts with EMBER_PACKAGED_WINDOWS_NODE_TEST=1 and the absolute exact built ZIP in EMBER_WINDOWS_NODE_PACKAGE. It stages the existing full voice/models/runtimes/remote payload plus the reviewed Node toolchain, with normal metadata, notices and fuses. The journey must use the shipped app's actual resources and full Home/Host path. The existing packaged dependency/file-only probe remains separate coverage and cannot substitute. Only the exact ZIP named after this successful journey is uploaded. Release depends on the supported gate and downloads that tested Server 2022 ZIP; Server 2025 independently verifies its own ZIP. The generic desktop/speech regression ZIP is not a release substitute.

The existing experimental-windows-controller.yml files-only ZIP job keeps its original explicit build, remote-parts, stage and archive recipe, without the Node staging flag. Its unchanged controller/dependency probe still requires the exact files-only inventory and zero executed checks. It does not call package:win, which now strictly requires the reviewed Node producer cache. This keeps file-only regression coverage usable on a fresh worker without inventing an asset fallback. Its windows-file-only-zip artifact cannot satisfy the required Node product gate or the release download.
