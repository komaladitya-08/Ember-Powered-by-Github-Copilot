# Ordinary-host control for the fixed libuv observer object

This separate experiment tests the emitted observer object's forwarding and LastError behavior with fixed local delegates on an ordinary Windows host. It does not call the five delegated Windows APIs, run an LPAC process, enable the original native probe, or execute project code. Actual Windows linking and execution are pending review and CI. The existing producer, observer C/header, flags, source/catalog pins, workflow, and hard-false LPAC/native guard remain unchanged.

The eighth compile-only run of [draft #240](https://github.com/komaladitya-08/Ember-Powered-by-Github-Copilot/pull/240), run `43924201426`, compiled head `9bcd829ff758c847aac515d02b91336c916f3d91` through merge `243b9bfd182894e397d756326bd6b166b7a7088a`. Linux passed 507 portable cases; Windows passed 484 with 23 expected platform skips. Its authenticated public artifact and unchanged receipt/PE/hash checks passed. Emission schema 2 remained refused: function 2 had two matching static delegate sites, and the records also showed two for function 4; the other four had one each, with no unknown external calls. The first refusal was phase 6/reason 16/function 2/count 2/mask 14. Static lexical sites do not establish dynamic invocation counts or LastError transparency. No listing or object was published or inspected as raw output.

The new issuer is `ember-experimental-windows-uv-observer-abi-control`. Its base recipe pin hashes the original 16 producer inputs. The builder invokes that unchanged producer once, checks its current source/build/tool receipt, and hashes the ordinary AMD64 observer object. It links that same file into a second target as a CMake external object, then rechecks the object, original source manifests, generated project, tool fingerprints, and both recipes. There is no observer recompilation, patched object, libuv aggregate, forced symbol resolution, or instruction decoder in the control target. Normal CRT initialization, `/MT`, and `/GS` remain enabled. The object envelope checker bounds ordinary COFF headers/sections/relocations/symbol-table extent; it does not interpret machine instructions or claim to validate every COFF semantic.

The C control defines five typed local `__imp_*` pointer data symbols and the plain `uv_translate_sys_error` stub. SDK declarations and the original header's type assertions remain in force. The final bounded PE import check rejects the five real API names from every DLL, ordinal imports, and delay imports. Startup or late CRT accesses to a substituted delegate are errors, rather than calls through to a live API. Whether the selected SDK/linker actually resolves these symbols as intended is a required ordinary-host result, not a fact established by Linux tests.

For each of six wrappers, the fixed matrix covers armed/unarmed, success/failure, set-marker/retain-seed, and two repetitions: 96 comparisons. Every comparison first runs the direct stub as a positive baseline, then the wrapper. Immediate LastError samples bracket each call. Checks cover every forwarded argument, high bits, stack arguments, mutable/output storage, exact return (including true BOOL value 7), one dynamic invocation, delegate-entry/caller LastError, and the original armed ledger. Controlled translation success retains the original observer's documented unknown state; the control does not change it to satisfy a success claim. This exercises only the fixed matrix, not every possible input or branch.

The only success frame is 256 bytes containing fixed counts, IDs, masks, and zeros. The runner requires natural exit zero, no signal/error, exact frame length, empty stderr, every fixed DWORD, and unchanged object/image/receipts/runtime inputs before writing `abi-result.json`. Nonzero status and uncertain process outcomes never grant stream readout. No pointers, command lines, paths, arbitrary messages, LastError values, ASM, raw object bytes, or compiler logs appear in the result. Acquired streams are wiped. Failed or timed-out staging is retained; the wrapper does not certify whole process-tree cleanup before the fresh CI VM is torn down.

This is trusted fresh CI staging, not exclusion of concurrent same-user mutators or standalone cryptographic attestation from arbitrary local receipts. The ordinary-host result binds the compile/run commit, original receipt digest, exact observer object digest, control image, and current runner/report recipe. Only the fixed PE, two receipts, LICENSE, and closed result are public artifacts. There are no arbitrary artifact, executable, script, provider, or argument inputs.

The new workflow is limited to its exact branch or deliberate manual invocation. Its first publication is held for review. It leaves the original compile-only workflow and LPAC guard intact. Even a successful ordinary-host control does not authorize the full native probe or establish real Windows API, LPAC, `uv_spawn`, Node, or general Windows coding compatibility. Any later native admission needs a separate reviewed decision and its existing controls.

## Primary source basis

- Microsoft describes [`dllimport` indirect `__imp_` calls](https://github.com/MicrosoftDocs/cpp-docs/blob/af4947c4bdf5993dcaee98e63d55a2d7a5744d7d/docs/build/importing-function-calls-using-declspec-dllimport.md), the [x64 register/stack convention](https://github.com/MicrosoftDocs/cpp-docs/blob/af4947c4bdf5993dcaee98e63d55a2d7a5744d7d/docs/build/x64-calling-convention.md), and [CRT security-cookie initialization](https://github.com/MicrosoftDocs/cpp-docs/blob/af4947c4bdf5993dcaee98e63d55a2d7a5744d7d/docs/c-runtime-library/reference/security-init-cookie.md). These support the design; they do not replace the actual link/control.
- Pinned [SDK declarations](https://github.com/microsoft/win32metadata/tree/15fc870a5e96df7c560877ff30136c0fb5a21e9b/generation/WinSDK/RecompiledIdlHeaders) specify the five APIs' types, including mutable `LPWSTR`, eight/ten argument calls, and pointer-sized `ULONG_PTR`. Installed SDK types are independently compile-asserted by the unchanged observer header; public repository bytes do not attest installed headers.
- [GetLastError](https://github.com/MicrosoftDocs/sdk-api/blob/656e9656bfaef34dd29cd7ee9e1146aec17e924c/sdk-api-src/content/errhandlingapi/nf-errhandlingapi-getlasterror.md) documents per-thread state and immediate sampling. Success may retain or change that state, hence both fixed modes.
- Pinned [CMake Visual Studio generator](https://github.com/Kitware/CMake/blob/859ca5c4d7396a011a462878179bc173e1283731/Source/cmVisualStudio10TargetGenerator.cxx#L2563) emits external object source entries as `Object`; the new readback requires exactly one fixed C source and one exact existing object. It also preserves the selected compiler/SDK/toolset, `_WIN32_WINNT=0x0602`, offline guard, and direct `/MT` scope checks.

## Validation

Linux actual-C tests use test-only declarations and exercise the unchanged observer plus the control logic with fault injection. They provide no Windows ABI, policy, real-API, or LastError evidence. All 141 new portable cases passed, including 19 actual-C logic cases. The combined original/new batch passed 647 of 648; the unchanged resource-reader subprocess-success assertion failed once. An isolated run of that unchanged suite passed 29 of 31 with different failing cases. One case elapsed 5018 ms against its existing 5000 ms subprocess bound, but the captured assertion exposed only a boolean: subprocess status/error and failure cause are not established. No reader source or deadline was changed. Scoped lint, seven module syntax checks, YAML/branch gates, original producer identity, and diff checks passed. TypeScript first exited 2 for a test mock's nonexistent typed `fs.default`; the one-line mock correction passed all 20 runner cases and lint, then the exact-final TypeScript check exited 0 (session `50080`). Actual Windows SDK linking, PE import readback, and the 96 ordinary-host comparisons remain pending.
